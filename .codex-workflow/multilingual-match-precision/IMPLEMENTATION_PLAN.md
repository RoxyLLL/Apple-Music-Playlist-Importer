# 实施框架

## 阶段1：复现与冻结样例
读取现有 dirty diff，保留用户改动。以 EVIDENCE.md 和截图为依据建立最小负例；缺失 ID/时长/ISRC 不补造真实值。额外的相近时长、同专辑等压力样例明确标注 synthetic。
比较冷缓存、旧缓存和当前规则计算路径。版本/构建未知时记录未知；无截图原始 JSON 时不把低分离线结果当作根因已解决。

## 阶段2：证据与查询模型
在 models.py 增加有默认值的证据/诊断结构；已有接口字段向后兼容。可新增 matcher/evidence.py、matcher/query_planner.py 以集中规则，不必大规模重构。
cleaner.py 区分标题与艺人转写上下文；有序去重，避免 set 遍历导致首个命中和查询顺序不确定。
别名数据附艺人作用域、证据来源URL与人工核实标志。原有安全别名继续支持，不能把整个旧词典无条件升级为已核实事实。

## 阶段3：评分和决策
scorer.py 保留实际 title_score/artist_score，不通过时长/Single改写标题分数。新增独立身份门槛与可解释冲突；不以提高统一分数阈值代替证据规则。
对纯汉字日语转写、罗马音片段包含、短名字、同曲版本豁免作定向修正。使用完整字符/词元覆盖指标和保守默认值，阈值由固定正负样例验证，记录选择理由。
初始匹配、ISRC批匹配、深度重试、手动候选排序、个人资料库候选最终都不能绕过统一的决策函数。人工选择显式标记，不伪装自动证据。

## 阶段4：有预算的召回
修正 engine.py 当前“先截取3个词、追加新词、只执行前2个”的排队方式，使新发现的官方译名能占据剩余查询槽位。
先原文+艺人；剩余槽位优先可靠译名+艺人。深度重试再用可靠艺人别名、完整转写和低权重单歌名。
例如有官方作用域别名时：灰かぶり 十明 → Cinder ella 十明；拉丁艺名只有确认后才加入。
预算覆盖所有地区而非每地区各自重置。401/403和429停止新增扩展，保留部分候选与错误状态。review不应阻止仍有预算的检索。

## 阶段5：缓存升级
单一规则版本常量、别名版本、配置指纹；旧记录读取兼容但不再信任旧自动决策。Catalog缓存与匹配结果缓存分开。
精确身份键与宽松召回索引分开。宽松文本命中只提供待重新验证候选，不带回旧 source_track、评分和默认选中。
同一来源的人工确认需要精确身份边界；本地资料库关联必须限定账号（只用不可逆内部标识，不导出用户 Token）。
新增旧版错误 auto_accept 注入测试和版本冲突测试，证明升级后无需用户手动清库即可生效。

## 阶段6：API、界面与诊断
统一徽标/默认选择函数，检查表格、弹窗、统计、批量高匹配按钮、重试合并及导出。
单曲诊断展示证据、冲突、缓存/规则版本和各查询实际执行状态。用户问题中的“作者”在本期主要指表演艺人；作词/作曲等角色标注仅用于解析，不假定其就是演唱者。
构建标识可来自打包时生成的元数据；源码运行和未知旧包明确区分，不在每次请求里运行git或假称版本相同即二进制相同。

## 阶段7：测试交付
先运行困难负例与正例，再跑整个套件。补充前端实际渲染/交互测试；可以用本地 mock API 的浏览器测试或可执行的 JS 测试加关键界面验图，记录步骤和断言，不能仅用 rg 搜索当行为测试。
全套使用临时用户目录、临时缓存、虚拟Token、HTTP阻断和外部进程mock，沿用上轮隔离方法。
交付 RESULT.md，列出改动、前后矩阵、规则变化、请求预算、旧缓存处理和测试命令结果，等待Codex验收。
