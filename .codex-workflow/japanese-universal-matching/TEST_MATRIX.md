# 强制测试与验收矩阵

## A. 通用规范化

|编号|场景|必须断言|
|---|---|---|
|A01|平假名、片假名、混合假名|稳定生成原文、假名统一和有限罗马字变体|
|A02|纯汉字日文歌名/艺人|可生成候选；标记 `ambiguous_cjk_only/weak`，不成为强证据|
|A03|全半角、长音、促音、拨音、中点、空格|等价规范化，不丢失原文|
|A04|罗马字带空格/连字符/长音符号|召回变体一致，数量有上限|
|A05|中文纯汉字输入|允许检索扩展但不被宣称为已核实日语读音|
|A06|随机 Unicode/空值/Emoji|不崩溃、不产生空查询或指数变体|

## B. 查询规划与 API

|编号|场景|必须断言|
|---|---|---|
|B01|原文目标区即命中|仅执行必要查询并早停|
|B02|英文艺名 + 日文歌名|动态组合进入执行序列，不需要静态艺人表|
|B03|日文艺名 + 罗马字歌名|动态组合进入执行序列|
|B04|纯汉字标题和艺人|算法生成查询真实执行，不靠 fixture alias|
|B05|本地化搜索|`l` 只取 storefront 支持值；缓存按 locale 隔离|
|B06|Apple suggestion 扩展|最多两条；无源 token 对齐的建议被拒绝|
|B07|目标区失败、JP 命中|调用 JP discovery，再批量 equivalents 回目标区|
|B08|equivalent 缺失但 ISRC 存在|执行目标区 ISRC 回查|
|B09|JP 存在、目标区不存在|返回 unavailable，最终候选不是 JP ID|
|B10|429/401/timeout|停止或按策略退避；不能缓存成 no_match|
|B11|预算|逐项断言 search/hint/equivalent 次数不超限|
|B12|确定性|不同 `PYTHONHASHSEED` 查询序列完全一致|
|B13|截图回归：`スパークル—幾田りら`|目标区无结果后真实进入 JP discovery 和回映射；不得新增该歌曲/艺人的运行时 alias 或缓存种子|

## C. 评分安全

|编号|场景|必须断言|
|---|---|---|
|C01|仅标题和艺人都由同一转写算法相似|只有一个弱证据族，不能 auto_accept|
|C02|同标题不同艺人|拒绝自动采纳|
|C03|同艺人不同标题但时长/专辑相同|至多 review|
|C04|Live/Remix/伴奏/翻唱/角色歌冲突|冲突不可被 equivalent 以外的弱信号绕过|
|C05|ISRC 一致无冲突|可自动采纳|
|C06|ISRC 一致但明确版本/艺人冲突|转 review 并解释冲突|
|C07|Apple equivalent 回映射|作为强身份链，但仍检查版本及主艺人冲突|
|C08|短标题、短艺名、共享汉字|子串或共同字符不构成身份一致|
|C09|搜索提示命中高相似候选|提示本身不提升 verification level|
|C10|目标区 ID、JP ID、文本相似候选混合|正确聚合，目标区实体优先|

## D. 缓存与迁移

|编号|场景|必须断言|
|---|---|---|
|D01|同 query 不同 locale|结果不串用|
|D02|同 JP ID 映射不同目标区|equivalence cache 严格隔离|
|D03|旧规则 auto_accept|重评且不能直接复活|
|D04|当前版本合法缓存|复用且不重复评分/请求|
|D05|用户确认|仅同源身份+目标区复用，不生成全局 alias|
|D06|旧 SQLite schema|原地迁移，人工确认保留，不清空整个库|
|D07|负缓存|错误不缓存；no-hit/equivalent-miss 使用有限 TTL|

## E. UI 与诊断

|编号|场景|必须断言|
|---|---|---|
|E01|review 分数很高|显示待复核且默认不勾选|
|E02|unavailable|显示目标区不可用，不出现“加入”默认选择|
|E03|错误/频控|显示检索未完成，可重试，不写成未收录|
|E04|重试结果替换旧结果|旧自动选择不残留|
|E05|诊断导出|含所有查询、locale、storefront、发现/映射链、版本和预算；不含秘密/路径|

## F. 覆盖率评估集

评估集不是运行时词典，至少包含：

- 200 个目标区可用正例：假名、片假名、纯汉字、混合文字、英文艺名、括号译名、不同本地化名各不少于 20 个。
- 100 个困难负例：同名不同艺人、同艺人相似歌名、Live/翻唱/伴奏/Remix、角色歌、短标题、中文同形汉字。
- 至少 30 个 JP 可见但目标区不可用或 ID 不同的跨区样例。

报告必须给出分桶指标和失败清单：Recall@20、MRR、auto_accept precision/recall、review/no_match/unavailable 数量、平均/P95 请求数。不得把测试 fixture 中的歌曲写进生产 alias/cache，也不得用 synthetic 100% 宣称真实曲库覆盖率。
